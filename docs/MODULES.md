| **Rebalance engine** | `execution/rebalance.py` | **Target vs actual, in € and after tax — and the book CLOSES.** Unbuyable model names are substituted from the same run's ranking, the residual rescaled (`close_target_weights`, capped by `max_dropped_pct`, else `MODEL BOOK INCOMPLETE`) and re-capped with `water_fill`, so `Σ target% + cash% = 100` with **CASH as a priced row**; the vehicle is resolved at table time from `etf_universe.yaml` (never off the frozen model row) and no non-HOLD row may name an unbuyable ticker (test-enforced). Model book (weights × deployable capital) vs the real book marked in EUR → per sector `gap_eur`, `rule_action`, `trade_eur`, CGT, `cost_drag_eur`, and a **`breakeven_pct`** — the trade's friction as a % of the capital it moves, i.e. what the destination must outperform the source by. Two blocks ride with the table: the **SWAP LEDGER** (`swap_ledger`, sells paired to buys largest-first, CGT pro-rated, legs under `min_ticket_eur` skipped) with its `rank_edge_evidence` line, and **PARTIALS** (`partial_rungs`, distance to BOTH rungs per held line — never a 'nearest', their units are not comparable). `net_edge_eur`/`expected_edge_eur` stay in the JSON and the lake as calibration input but no longer drive the table. Actions are `SELL>REDUCE>TRIM>RE-SCORE>ADD>BUY>HOLD` in fixed precedence — **no watch/monitor/consider exists in the enum** (`BANNED_ACTION_WORDS`, test-enforced). **`RE-SCORE`** moves no money: a MISSING rank breaks the out-of-cut streak instead of counting as "outside it", and a sector absent from ≥`rescore_if.missing_runs_min` of the last runs gets this action rather than a SELL built on measurements nobody took. Streaks count one run per DATE (two same-day runs are one review cycle). The after-tax gate arms only on `gate_status`'s joint condition — enough independent windows AND |IC| ≥ `min_abs_ic` AND a POSITIVE sign; a negative composite IC disables it rather than inverting the profit-taking rule (`calibration.composite_ic`). Deployment ratio replaces cash-by-feel — and the SHORTFALL is now an action with a persistence rule (`shortfall_pp` in points of TOTAL capital + `shortfall_status`, `deployment.max_shortfall_pp` × `max_shortfall_runs`, counted per REVIEW DATE): breached, the review must execute or override in writing, naming the shortfall. **`cash_drag`** prices the idle capital against the benchmark it declined, counted from the last MOVEMENT, so the cost of NOT acting rides on the same strip as the friction of acting. **`unrecorded_deviations` + `_log_unrecorded`** read the previous run's non-HOLD rows against `data/movements/` and the override log and write what is left as DEFERs authored `unrecorded` — quiet used to be the cheapest conservatism and it was free. **Thresholds FROZEN 2026-08-28** (`rebalance_rules.frozen`) — changing one is a config edit + a CHANGELOG line, never a mid-review adjustment. **`score_decisions` / `decision_scorecard` audit the TABLE ITSELF** on the same clock: every recorded `rule_action` priced over a complete `scorecard.horizon_days` window against the **HOLD baseline** ('did acting beat leaving the book alone', not 'did the names go up' — that is beta), with the forward return signed by `action_direction` so a positive `rule_edge_pp` always means the rule was right. A verdict needs `min_n` AND `min_effective_windows` non-overlapping horizons; below either it says `not scoreable yet`, and with no complete window it does not fetch a price at all. Evidence for a config edit, never an edit. Deviations go to lake `override_log` and are **scored** ~21 trading days later as `(trade_chosen − trade_rule) × EUR forward return`, tallied by author; Claude's authorship is suspended arithmetically on a net-negative record (≥5 scored). Recommend-only. Config `scoring_weights.yaml` `rebalance_rules`. CLI `[--strategy X] [--json] [--no-persist]` · `override <sector> <action> --reason --author --trade-eur` · `overrides` · `scorecard` |

**Storage architecture — two tiers (parquet-first, no database).** See `docs/PLAN_lake_dvc_serving.md`.
- **Tier 1 (git, hand-edited):** config YAML, schemas, and the JSON *documents* skills Read/Write directly (sector_studies, theses, catalysts, taxonomy_proposals). These stay JSON forever — they are the skill interface. The `*_repo.py` modules read these files directly and print digests; writing a file IS the registration (no import step).
- **Tier 2 (parquet lake, git):** all computed time-series — momentum/flow snapshots, score_run/sector_snapshot/rank_event, indicator history, portfolios. Durable, versioned, queryable. Claude never Reads parquet directly — skills get tabular data via a Python CLI emitting JSON to stdout (`lake_query`, `snapshot_repo`).

**SQLite was removed entirely (2026-06-05).** It used to be a Tier-3 query cache, but it was never the source of truth (the files and the lake are), and the `llm_log` table it carried is obsolete now that there is no self-hosted LLM. Reads/writes of computed series go through `catalyx.store.lake`. There is no `CATALYX_DB_URL`, no `init`, no SQLAlchemy.

**Skills call Python modules** using `uv run python -m catalyx.<module> <command>` via Bash tool. This is the integration model — not a separate CLI for the user, but Python as a deterministic backend that skills invoke.
